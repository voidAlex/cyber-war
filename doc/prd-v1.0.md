# 《赛博战争模拟器》产品需求文档 (PRD) V1.0

> **审核修订版 v1.0.1**
> 
> 审核日期：2026-03-08

## 1. 产品概述

**产品名称**： 赛博战争模拟器 (Cyber War Simulator)

**产品定位**： 一款以"自然语言交互"为核心、由大语言模型（LLM）驱动的硬核大战略与态势推演游戏。

**核心体验**： 玩家扮演最高统帅，坐在沙盘前，告别传统的鼠标微操。通过自然语言向 AI 参谋长下达宏观战略指令，与拥有独立人格的敌我 AI 将领进行基于战争迷雾的盲盒博弈。

**技术基调**： 纯文本驱动的异步状态机，重逻辑、重并发、高扩展性。前端强调极客感的数据展示，后端依托多 Agent 协同与 Agentic Search 技术。

## 2. 核心架构

- 高信息密度的全息指挥控制台。强调数据表格、态势沙盘、以及流畅的自然语言对话式交互体验。

- 回合状态结算、多 Agent 调度以及流式对话输出。

- **状态持久化与记忆检索**：游戏状态以 **JSON 格式**持久化到**本地文件系统**（Tauri 应用数据目录），作为唯一真相源。event-log 采用 `.jsonl` **真追加（O(1)）**，回放从日志原文恢复。Markdown 文件仅用于审计日志和 LLM 上下文组装（不作为真相源）。

- **桌面应用形态（Tauri 2）**：本产品为 **Tauri 2 桌面应用**，前端实现所有的文件操作和业务逻辑，通过 Tauri Rust 后端访问本地文件系统。文件 IO 采用**原子写（临时文件 + rename）**，避免半写损坏。Windows/Linux 跨平台打包，无浏览器配额限制。

- **本地文件系统持久化**：本地文件系统持久化保存游戏状态，**桌面应用无 Safari OPFS 7 天清除之类的问题**。建议玩家定期手动导出存档 ZIP 作为备份，以防磁盘故障或误删。

- **存档机制**：本地文件系统静默存档 + 手动导入导出为 ZIP。

## 3. 核心机制：同步回合制 (WEGO) 与交互闭环

游戏时间非实时流逝，而是以"天/战役阶段"为单位推进，解决大模型响应延迟问题的同时，还原真实的统帅部运作节奏。

**规划期（时间静止）**： 玩家观察沙盘，与"参谋长 AI"对话。

**指令防呆与握手协议（批量握手）**：
- 玩家输入自然语言（如："让第一装甲师去左边"）。
- 参谋长 AI 拦截模糊指令，结合沙盘网格在前端弹出"预演虚线"，并反问明确（"长官，是否确认第一装甲师向西移动至 C3 网格？"）。
- **批量握手**：参谋长 AI **一次性批量解析**本回合多条模糊指令，前端汇总成"指令清单 + 预演虚线"，玩家**批量确认**（如一次确认/修改 5-10 条），无需逐条等待。玩家点击 [确认执行] 后，指令才会被转化为结构化数据，并写入本阵营的待执行队列中。

**集中结算期（沙漏时刻）**：
- 玩家点击"推演下一天"，双方计划锁定。
- 物理引擎计算战况，导演部 Agent 裁定战果（**导演部拥有最终裁定权**）。
- **回合结算延迟优化**：通过**真并行 + Prompt Caching + 流式战报**降低延迟与体感等待：
  - 战区司令与敌/盟统帅 Agent **真并行**执行（sequence 预分配保证确定性），重叠耗时。
  - **Prompt Caching**（系统提示 / 人格 / 历史 / 战役设定）命中缓存，降低单次请求延迟与成本。
  - **流式战报 TTFT<200ms**：结算中段即可见战报流出，玩家边等边看。
  - 显示每个 Agent 的实时状态（如"敌方司令思考中..."、"导演部裁定中..."）。
  - 单 Agent 超时 30s 硬限，失败降级规则引擎（见 §3.2 离线可玩降级）。

### 3.1 确定性两层分明

游戏的确定性分**物理层**与**导演层**两层，互不混淆：

- **物理层（纯数值，可重算可复现）**：物理引擎基于战役规则公式 + 确定性随机种子做纯数值计算。种子 = `scenarioSeed + ':' + turnIndex + ':' + sequence`，sequence 由 Agent 编排预分配（参谋批次 0+ / 战区批次 1000+ / 敌盟批次 2000+ / 导演批次 3000+），与调度/完成顺序无关。给定相同种子，物理层结算结果完全可复现；CI 固定种子回归比对 event-log 哈希。
- **导演层（LLM 输出，记录即真相）**：导演部 Agent 的裁定、战报润色、随机事件等 LLM 产出，写入 event-log 后**即视为真相**。回放时**从 event-log 读原文、不重算 LLM**。

**event-log 溯源标记**：每条事件标注 `source:'physics' | 'director' | 'rule-engine'`。回放时：`physics` 类校验重算一致（确定性保证），`director` 类直接采信原文（不重算），`rule-engine` 类见下节。**明确：确定性种子只保证物理层，不约束 LLM 输出。**

### 3.2 离线可玩降级

桌面应用**无 LLM 也可玩**：当无网络 / API Key 未配置 / LLM 超时或降级时，**规则引擎（physics-rules + 数值人格）接管推进游戏**，玩家仅失去叙事润色（战报为模板文本），核心博弈与数值结算不受影响。

- 降级期间 event-log 标注 `source:'rule-engine'`，UI 明示"当前为规则引擎降级结算"，**绝不编造不存在的 unit/坐标**。
- 设置可选**"纯规则引擎模式"**：零成本、零延迟，全程数值结算 + 模板战报，适合快速推演或离线单机。
- 在线时优先 LLM，离线/超时无缝降级到规则引擎，游戏不中断。

## 4. 多 Agent 层级网络与职责隔离

系统内置多类独立 Agent，形成复杂的指挥树与博弈生态：

**参谋长 Agent (玩家侧)**： 实时在线的翻译官。只能看到玩家视野内的情报，负责指令的明确化转换与风险提示。

**战区司令/长官 Agent (多层级实体化)**： 玩家和敌方/盟友阵营都有。玩家可向"集团军司令"下达宏观指令（如"三天内拿下某高地"）。该 Agent 拥有**数值基底人格**（`aggression`/`obedience`/`preferredTempo`/`doctrineTags` 等数值字段），LLM 在这些数值约束内发挥，把宏观指令拆解为底层连队的具体 JSON 行动指令。**obedience 低时按概率抗命**（director 依据 obedience 数值判定是否服从/打折执行），存在抗命或索要物资的博弈空间。人格有数值锚，非纯随机漂移。

**敌方/盟友统帅 Agent (独立阵营)**： 拥有独立视野与账本，可指挥自己的战区司令/长官 Agent 进行行动。盟友不受玩家直接控制，玩家需通过自然语言进行外交谈判（如请求空中支援），盟友有概率掉链子。

**导演部 Agent (裁判)**： 拥有上帝视野。每回合结束时，读取各阵营指令，**拥有最终裁定权**，可基于 LLM 判断调整物理引擎结果。处理玩家的"超常规奇招"（如赛博渗透、切断水源），生成天气突变等随机事件，并将最终战损润色为沉浸式战报分发给各阵营。

**物理引擎（JS实现）**： 基于战役规则进行数值计算，提供参考数据供导演部裁定。

## 5. 战场沙盘

- 回合结束后，导演部根据上回合的结果更新沙盘
- 沙盘非真实地图，而是类似即时战略游戏的网格状

## 6. 战争迷雾与情报系统

摒弃传统 RTS 的黑色遮罩，采用以文本为核心的情报置信度展示。

**情报颗粒度**： 统一语义 **Level 0=盲区、Level 3=全量透视（数值越大=越清晰）**，与代码实现完全一致。分为：
- Level 0（盲区）：完全不可见。
- Level 1（热力脉冲）：模糊迹象。
- Level 2（编制确认）：虚线边框军标。
- Level 3（全量透视）：显示精确血量/燃油。

**情报半衰期**： 失去实时侦察后，敌军图标化为半透明残影，并附带时间戳（如 [T-24h]）。玩家需自行判断敌军是否已转移。

**战略欺骗**： 支持部署充气坦克、虚假通讯节点，以假情报误导敌方统帅 AI。

## 7. 战役与剧本插件化引擎

游戏无固定战役，全量数据通过外部配置文件动态加载。战役包为 **ZIP 文件格式**，包含：

- **地图**：定义六边形/区域网格、地形通行阻力、高价值节点。
- **阵营**：定义阵营基础属性与外交关系。
- **装备**：底层装备数据库（如装甲厚度、火力值、油耗系数）。
- **坐标与编制**：开局各部队的网格坐标、编制及统领将领的 Agent ID。
- **特殊规则**：战役特殊规则（胜利条件、历史事件触发条件）。
- **数值计算规则**：装备的武力值、防御值、损失计算公式等等。
- **角色**：定义每个阵营的统帅、战区司令/长官 Agent 的性格、操作风格。

### 7.1 内置战役生成器

游戏内置**战役生成器**：玩家用自然语言提需求（历史战役名 / 时段地区 / 自定义约束），通过接入的 LLM + 多 Agent **基于历史事实**自动生成符合七文件 schema 的可玩战役包，导入即玩。把"战役插件化"与"LLM 驱动"结合，实现内容无限扩展。

**生成流程（多 Agent 协作，复用主游戏 Agent 编排基础设施）**：
1. **史实研究员 Agent**（Agentic Search）：检索可信来源 + LLM，查战役的时间 / 双方 / 指挥官 / 地理 / 兵力 / 关键节点 / 胜负与来源，作为"根据历史事实"的依据。
2. **战役设计师 Agent**（复用导演部角色）：把史实转游戏机制——map（地理网格 + 高价值节点）、factions、units、commanders（人格数值）、rules、victory。
3. **平衡校验 Agent**：检查数值平衡、胜利条件可达、规模合理，必要时迭代修正。
4. **schema 校验 + 兜底**：生成结果用 `campaign-schemas/` 的 ajv 严格校验；校验失败反馈 Agent 修正，多次失败降级为模板包。

**设计要点**：
- **玩家确认**：生成后预览/编辑再确认导入，不直接覆盖。
- **史实幻觉控制**：研究员 Agent 标注关键事实来源；虚构/自定义战役明确标注"非史实"。
- **缓存优化**：生成器 prompt 的"七文件 schema 定义 + 生成规则 + 历史校验规则"是固定 L0 前缀，多 Agent 共享 → 高缓存命中。
- **确定性**：生成包带固定 seed、生成后可回放；生成过程允许非确定（LLM 创作），产物固化即可。
- **史实来源策略：LLM 内置知识为主**（快、可离线、契合单机桌面定位，Rust 后端无需联网能力）。著名战役足够；冷门/不确定事实由平衡校验 Agent 标注"存疑"并提示玩家核对。

### 7.2 默认示例包：凡尔登战役 1916

作为**默认示例战役包**随产品分发，用于：① 加载验证（ZIP 导入闭环）② 端到端验收 ③ AI 行为合理性校验（史实可对照）。

- **时间**：1916/02/21 – 12/19（约 10 个月），一战西线最长最惨烈战役，"凡尔登绞肉机"。
- **双方**：德国（攻）vs 法国（守），消耗战，双方共约 71 万伤亡。
- **指挥官（映射人格数值系统）**：
  - 法国 **贝当 Pétain**：2/25 起任前线指挥，稳健防御 + 后勤轮换（"神圣之路"），obedience 高、aggression 低、tempo=methodical。
  - 法国 **尼韦勒 Nivelle**：5/1 接替贝当，反攻激进，aggression 高。
  - 德国 **法金汉 Falkenhayn**：消耗战略"让法国人流尽鲜血"，methodical、aggression 中、不追求速胜。
- **地理（映射沙盘）**：**默兹河两岸**，东岸德军主攻；高价值节点：**杜奥蒙堡 Fort Douaumont**（2/25 陷落，10 月法军收复）、**沃堡 Fort Vaux**、苏维尔堡、凡尔登城。

## 8. 前端 UI/UX 布局要求

**中央主视窗**： 2D 态势沙盘。支持网格高亮、战线绘制、情报热力图渲染及残影显示。

**右侧交互区**： 核心通讯终端。用于自然语言输入，展示战报。支持"字图联动"（点击战报中的地名，沙盘自动平滑跳转并缩放至该网格）。

**左侧看板**： 实时动态大盘。展示部队建制表、后勤物资流转图表、盟友信任度指示器。

**底部日志台**： 滚动输出底层代码引擎的细颗粒度物理事件（如 04:00 [D3] 车队遭袭，损失燃油 20%），拉满极客感。

## 9. 产品形态

- **桌面应用（Tauri 2）**：**Tauri 2 桌面应用**形态。前端 React + TypeScript 负责所有业务逻辑和渲染，**Rust 后端仅做两件事**：① 本地文件 IO（原子写 + 真追加） ② LLM 真流式转发。Rust 后端零行业务逻辑。Windows/Linux 跨平台打包。
- **玩家自带 API Key**：不提供 LLM API 服务，玩家自行输入 API Key 后才能进行游戏。⚠️ Rust 后端仅转发请求、不存储 API Key（明文即用即抛），并做 host 白名单 + 私网/元数据 IP 拒绝（SSRF 防御）。**apiKey 经操作系统凭证库加密保存**（Linux Secret Service / macOS Keychain / Windows Credential Manager；keyring 不可用时降级明文文件 + 警告），桌面端无需应用层口令、重启自动加载。本项目开源，代码可供审计。
- **推荐供应商：DeepSeek v4**：
  - **deepseek-v4-flash**：默认供应商。便宜、并发高、支持非思考/思考模式切换。OpenAI 兼容格式，base_url `https://api.deepseek.com`。
  - **deepseek-v4-pro**：高质量决策，仅用于导演部终裁、关键超常规奇招等需要强推理的场景。
  - **缓存红利**：DeepSeek 上下文硬盘缓存默认开启，**缓存命中价是未命中的 1/50~1/120**，通过 prompt 分层（L0 永久 system prompt / L1 战役设定 / L2 世界状态摘要 / L3 具体指令）让前缀稳定，多 Agent 共享前缀互相命中，优化指标目标命中率 >80%。
  - welcome-screen 供应商选择：DeepSeek 设为**推荐默认**（仍保留 openai/anthropic/custom）。
- **战役/剧本**：**ZIP 文件导入** + **内置战役生成器**（见 §7.1）。玩家可从官方渠道或社区获取战役包 ZIP 文件导入，或用生成器按需生成。默认附带凡尔登战役 1916 示例包（见 §7.2）。

### 10.2 风险提示

| 风险点 | 描述 | 缓解措施 |
|--------|------|----------|
| 人格漂移 | 数值基底 + LLM 在约束内发挥，仍可能不稳定 | 数值锚定 + obedience 低时按概率抗命 |
| 命令确认延迟 | 多条命令批量解析/确认 | 批量握手 + 流式输出 + 进度条缓解 |
| 存档丢失 | 本地文件系统损坏/误删 | 原子写 + 建议定期导出备份 |
| 结算等待 11-15s | 玩家等待体验 | 真并行 + Prompt Caching + 流式战报 TTFT<200ms |

|------|----------|--------|---------|
| **deepseek-v4-flash**（80% 命中） | 默认供应商，绝大多数场景 | ≈ ￥0.0021 | **≈ ￥0.064** |
